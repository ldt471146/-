# Feature Specification: 全流程编程学习平台能力补齐

**Feature Branch**: `001-fullflow-upgrade`  
**Created**: 2026-02-12  
**Status**: Draft  
**Input**: 用户给出的“任务目标 + 主要任务与要求”，并结合当前代码现状进行差距分析

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 学生完成“学-练-测”闭环 (Priority: P1)

学生可以从课程学习进入练习，再进入在线测评并收到明确反馈，形成完整学习闭环。

**Why this priority**: 这是平台核心价值，直接决定项目是否满足“入门-练习-提升”的主目标。

**Independent Test**: 使用学生账号完成“选课 -> 学习课时 -> 做题/编程题 -> 查看成绩与错因”全流程即可独立验收。

**Acceptance Scenarios**:

1. **Given** 学生已登录并加入课程, **When** 完成课时并提交练习, **Then** 系统记录学习进度与题目结果。
2. **Given** 学生在测评中心提交 Python/C++ 代码, **When** 判题完成, **Then** 返回得分、通过数、错误信息且可再次提交。

---

### User Story 2 - 教师可发布教学内容与测评任务 (Priority: P1)

教师可以管理课程、章节、题目、编程题，并发布考试任务，查看学生提交结果。

**Why this priority**: 教师端能力决定平台内容供给和教学组织能力，是学生端可持续运行前提。

**Independent Test**: 使用教师账号创建课程与题目，发布考试任务，学生参与后教师可看到结果统计。

**Acceptance Scenarios**:

1. **Given** 教师具备权限, **When** 新建题目和测试用例, **Then** 学生可以在测评中心看到并提交。
2. **Given** 教师创建考试任务并发布, **When** 学生交卷, **Then** 教师可查看任务和提交记录。

---

### User Story 3 - 管理员具备平台治理能力 (Priority: P2)

管理员可以管理用户角色与状态，审核课程与社区内容，保障平台安全和秩序。

**Why this priority**: 平台进入多人使用阶段后，治理能力是稳定运行的必要条件。

**Independent Test**: 使用管理员账号完成“审核教师申请、禁用用户、审核帖子/课程”并验证权限隔离。

**Acceptance Scenarios**:

1. **Given** 管理员登录, **When** 审核教师申请, **Then** 申请状态、角色关系、通知状态一致。
2. **Given** 管理员执行内容审核, **When** 删除违规内容或禁言, **Then** 普通用户不可继续访问对应内容或互动。

---

### User Story 4 - 学习路径推荐可用 (Priority: P2)

系统基于知识点依赖关系向学生推荐“已学/待学/下一步”路径。

**Why this priority**: 这是总需求中的差异化能力，直接提升学习效率与个性化体验。

**Independent Test**: 构造一组知识点依赖并完成部分学习记录，验证推荐路径正确变化。

**Acceptance Scenarios**:

1. **Given** 课程配置知识点依赖, **When** 学生完成前置知识点, **Then** 下游知识点状态由“待学”变“可学”。
2. **Given** 学生进入学习中心, **When** 查看路径面板, **Then** 清晰展示已学、待学、推荐下一步。

---

### User Story 5 - 社区互动闭环上线 (Priority: P3)

学生可发帖提问、他人回复、教师标记最佳答案，管理员可审核与治理。

**Why this priority**: 属于增强能力，提升留存和学习互助，但不阻塞 MVP 教学闭环。

**Independent Test**: 完成“发帖 -> 回复 -> 教师标记最佳答案 -> 管理员审核”的完整链路。

**Acceptance Scenarios**:

1. **Given** 学生发布问题帖并附代码片段, **When** 他人回复, **Then** 帖子页可展示完整讨论串。
2. **Given** 存在违规帖, **When** 管理员审核删除或禁言, **Then** 内容不可见且操作可追踪。

---

## Current Baseline Analysis

### 已实现（可复用）
- 账号认证：邮箱注册/登录、JWT、角色权限控制（STUDENT/TEACHER/ADMIN）
- 学生学习与测评：课程、学习记录、题库、编程题、本地判题（Python/C/C++）、考试与成绩
- 教师能力：课程/章节/课时管理、题库/编程题管理、考试任务发布
- 管理能力：教师申请审核
- 报告能力：成长报告总览与趋势（当前为 SVG 可视化）

### 部分实现
- 数据统计：已有基础统计，但缺“班级维度排行、导出”
- 管理端：仅教师申请审核，尚无完整用户管理/课程审核

### 未实现
- 社区互动（帖子、回复、最佳答案、审核、禁言）
- 学习路径推荐（知识点图谱与推荐规则）
- 注册时“学生需家长手机号验证”完整流程
- ECharts 集成（当前报告页未使用 ECharts）

## Edge Cases

- 代码提交超时、编译失败、运行时异常、空代码提交
- Redis 不可用时模拟考试快照降级
- 角色越权访问（学生访问教师/管理员接口）
- 考试开始/结束时间边界
- 重复提交、并发提交导致的数据一致性
- 帖子违规词、恶意代码片段、超长内容

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持学生、教师、管理员三类角色的账号体系与权限隔离。`[已实现]`
- **FR-002**: 系统 MUST 支持邮箱注册与登录，密码 MUST 使用 BCrypt 存储。`[已实现]`
- **FR-003**: 系统 MUST 支持学生端课程学习、进度记录、续学定位。`[已实现]`
- **FR-004**: 系统 MUST 支持题库做题、错题本、收藏、统计。`[已实现]`
- **FR-005**: 系统 MUST 支持 Python/C++ 在线提交、编译执行、测试用例判定与反馈。`[已实现，C++/Python满足]`
- **FR-006**: 系统 MUST 在代码评测结果中返回得分、通过数量、错误信息。`[已实现]`
- **FR-007**: 系统 MUST 支持教师发布课程、章节、课时、题目、编程题。`[已实现]`
- **FR-008**: 系统 MUST 支持教师发布考试任务并查看学生提交结果。`[已实现]`
- **FR-009**: 系统 MUST 支持管理员审核教师申请。`[已实现]`
- **FR-010**: 系统 MUST 支持学生注册时家长手机号验证流程。`[待实现]`
- **FR-011**: 系统 MUST 支持学习路径推荐（基于知识点依赖关系）。`[待实现]`
- **FR-012**: 系统 MUST 支持社区帖子发布、回复、代码片段展示。`[待实现]`
- **FR-013**: 系统 MUST 支持教师标记最佳答案。`[待实现]`
- **FR-014**: 系统 MUST 支持管理员进行帖子审核、删除、禁言。`[待实现]`
- **FR-015**: 系统 MUST 支持管理员用户管理（启用/禁用、角色调整）。`[待实现]`
- **FR-016**: 系统 MUST 支持管理员课程内容审核。`[待实现]`
- **FR-017**: 系统 MUST 支持教师查看班级维度统计并导出。`[待实现]`
- **FR-018**: 系统 MUST 提供青少年友好界面和明确引导提示。`[部分实现]`
- **FR-019**: 前端 MUST 对未登录用户限制学习与测评模块访问。`[已实现]`
- **FR-020**: 报告模块 MUST 基于 ECharts 提供折线图/雷达图/饼图。`[待实现]`

### Key Entities

- **User**: 用户主体，含角色、状态、联系方式、禁言状态
- **Role**: 角色定义与权限映射
- **Course/Chapter/Lesson**: 课程内容结构
- **KnowledgePoint**: 知识点节点
- **KnowledgeDependency**: 知识点先后关系（有向边）
- **LearningPathState**: 用户在知识点路径上的状态
- **Question/QuestionOption**: 客观题及选项
- **CodeProblem/Testcase/CodeSubmission**: 编程题、用例、提交记录
- **ExamTask/ExamSubmission**: 考试任务与成绩记录
- **Post/PostReply/BestAnswer**: 社区帖子、回复、最佳答案
- **ModerationAction**: 审核、删除、禁言等治理记录

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 学生可在 3 分钟内完成“学习-练习-测评-查看反馈”闭环。
- **SC-002**: Python/C++ 判题流程在正常负载下 p95 响应时间 <= 3 秒。
- **SC-003**: 50 名学生并发提交代码时，核心接口成功率 >= 99%。
- **SC-004**: 角色越权访问拦截率 100%（教师/管理员接口不被学生访问）。
- **SC-005**: 社区违规内容在管理员审核后 1 分钟内不可见。
- **SC-006**: 学习路径推荐命中率（推荐节点满足依赖规则）100%。
- **SC-007**: 提交可运行原型、开发文档、测试报告，覆盖需求到测试闭环。
